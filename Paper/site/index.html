Abstract

Explainable artificial intelligence (XAI) seeks to explain how an AI system arrived at a particular output. Many common XAI methods function by measuring the sensitivity of an AI output to changes in various model inputs, requiring unfettered model access to make multiple model inferences per explanation. This is computationally expensive, vulnerable to adversarial attacks, and unviable if a third-party restricts model access for an AI audit. New approaches are hence necessary to enable XAI in emerging applications: (a) zero shot classification using large language models (LLMs), (b) AI auditing of opaque black-box systems that do not provide model access, and (c) the use of AI in scientific discovery. We propose Rule-of-Thumb (RoT) explanations — a new approach to XAI based upon a novel mathematical formulation that identifies the most relevant features for predicting the behaviour of a machine learning (ML) model, for a particular datapoint. We show how RoT is well suited to enable XAI in each emerging application listed above. Additionally, RoT meets specific requirements from leading AI regulations, provides a familiar interface and visualisations for XAI practitioners, is completely model-agnostic and makes no causal assumptions, and is significantly faster in practice than alternative XAI algorithms. Introduction

To understand how explainable AI (XAI) could work, we consider an example from one of the earliest texts on medical statistics [1]. Suppose we wished to know where a doctor was on Wednesday night. If we know that most Wednesday nights, they visit the cinema, we might assume they are there. However, if we know they are currently housebound with a broken leg, we would become confident that they were at home. Meehl [1] argued that one advantage of an expert over the statistical models of the time, was that an expert could take advantage of these rare events to change their predictions. Inspired by this, we propose RoT, a new form of XAI that quantifies the predictive importance of each feature value, or piece of information, about a particular datapoint.

This is a clear departure from existing approaches. Popular approaches to explainable AI (XAI) are variants of sensitivity analysis. The underlying intuition behind these approaches is that by perturbing the inputs to a machine learning model, we can identify those inputs that the model is most sensitive to, i.e. the input which upon modification, causes larger changes in the model output. These explainers such as LIME[2], SHAP[3], and many more[4] provide post-hoc local feature-importance explanations which describe how sensitive a model output is to each input feature for a particular datapoint. Explanations generated using these explainers are signed vectors representing the importance of each input to the output for a given prediction. Benchmarks to evaluate explainers also often work by verifying that model sensitivity or model gradients match purported feature importance scores. These forms of explanation are increasingly being used to debug models during development, audit black-box AI systems after deployment, or even to understand model training data to propose scientific hypotheses.

Such approaches have received substantial criticism. As each feature is artificially perturbed, sensitivity analysis relies on the response of the model to synthetically generated data. This data generation fails to capture causal dependencies between variables, and can create out-of-distribution data that could never occur in the real world. Performing sensitivity analysis implicitly relies on at least three fundamental assumptions: 1. it is possible to pass new datapoints to the model and see how the output alters; 2. perturbing the input results in meaningful changes of the output; and 3. these changes in model output also occur with real-world data.

These assumptions make existing forms of XAI inapplicable in three of the most important use cases. 1. Auditing external models where we do not have control over the inputs to the model. 2. Zero-shot classification using large language models (LLMs) where models output boolean yes or no responses based on input text rather than the continuous scores required for sensitivity analysis to work reliably. 3. Scientific Discovery using XAI where AI models are trained on real-world scientific data, and explanations are sought to uncover natural phenomena rather than explain the AI model. Because the models trained may fit the data without matching real-world causal dependencies, their explanations do not faithfully capture scientific relationships. The SHAP explanation in Figure 1 can only propose valid scientific hypotheses to the extent that the trained AI model accurately predicts behaviour on never seen before out-of-distribution data.

We consider an alternate approach that bypasses these limitations. Rather than formulating XAI in terms of how changes in feature value alter model output, we ask how knowledge of particular feature values should alter our predictions of the model's behaviour. We see echos of this idea in an early work on medical statistics [1] that argued that one of the benefits of an expert's prediction over that of a general statistical model is that the expert can exploit important information that occurs too rarely to be captured by a general model. Following this, an unconsidered form of XAI would be to highlight the information most useful for an expert trying to predict model behaviour.

RoT Formulation

We assume that our expert has already uniformly sampled an unknown subset of features* with probability $p$, and wishes to know which features are most likely to be useful to look at next. We make some simplifying assumptions to answer this efficiently. Given a model $C(\cdot)$ defined over features $\mathbb{J}$, and dataset $X$, we want to find the optimal set of additive functions such that for any subset of features $J \subseteq \mathbb{J}$ and datapoint $x \in X$ we can estimate $C(x)$ as:

$$C(x) \approx F \left( \sum_{j \in J} f_{\theta_{j}}(x_j) + G \right) \quad \forall J \in \mathcal{P}(\mathbb{J}) \quad \text{(Equation 1)}$$

where $f_{\theta_j}(x_j)$ is a learnt function representing the information provided by knowing that the $j^{\text{th}}$ feature takes value $x_j$, and $G$ a global bias term that indicates what prediction should be made without knowing anything about the datapoint $x$. We refer to $f_{\theta_j}(x_j)$ as the importance of a feature $j$ taking value $x_j$. This corresponds to how much a prediction of $C(x)$ should update, on average, after discovering this information.

Given any random subset of features, we can always approximate $C(x)$ using the sum of importances. This idea of always having a rough estimate given any amount of limited information gives rise to the name of the method Rule of Thumb. To find the optimal weights $\theta_j \forall j \in \mathbb{J}$ for our model, we minimize the following objective $\mathcal{L}$:

$$\min_{\theta} \mathcal{L} = \min_\theta \sum_{ {J} \subseteq \mathbb{J}} \sum_{x \in X} \left( p^{|J|} (1-p)^{(|\mathbb{J}|-|J|)} \cdot \ell\left[ C(x), F \left( \sum_{j \in J}f_{\theta_{j}}(x_j) + G \right) \right] \right) \quad \text{(Equation 2)}$$

Here the term $\ell\left[ C(x), F \left( \sum_{j \in J}f_{\theta_{j}}(x_j) + G \right) \right]$ is a standard training loss such as log loss or squared error that penalizes mispredictions of $C(x)$. This loss is not only marginalized over all datapoints, as is common in standard machine learning, but also all possible masks of the data. Although computing $\mathcal{L}$ exactly is expensive and requires computing the standard loss over the entire dataset $2^{|\mathbb{J}|}$ times, it can be efficiently optimized using stochastic gradient descent with dropout[6] applied to the feature importances $f_{\theta_{j}}(x_j)$. Using dropout, the training time for fitting is almost the same as fitting the simple additive form of Equation 1 that does not consider subsets of features.

After fitting the model, the feature $j$ with the largest absolute value $|f_{\theta_j}(x_j)|$ is the one that will most change our confidence in the prediction, and by sorting the features by absolute value, we obtain a ranking of feature importance.

Comparison with Existing Methods

Gradient-based methods[4] are computationally efficient but require direct access to model weights, which are often proprietary. With LLMs it is common to provide access only via an application programming interface (API) access. Gradient-based approaches cannot be applied to any model that only offers API access.

Sensitivity-based approaches LIME and SHAP optimise a per-datapoint objective. While RoT masks information and fits one model for the entire dataset, these approaches perturb datapoints and fit one linear model per datapoint. This creates substantial differences in applicability — not only is sensitivity analysis badly suited for analyzing opaque models that only return yes/no decisions (such as those provided by an LLM API), but it also requires many times (typically ×500 to ×5000) more model or API calls to explain each prediction. Finally, by definition, sensitivity analysis can explain models only in terms of their inputs. RoT can utilise non-input features by fitting on extended datasets if required. This enables explaining model predictions using external models such as BERT[7] to generate more informative explanations.

Of existing approaches, RoT is closest to SHAP. While RoT reveals how informative it is to know on average that a feature takes a certain value, SHAP reveals the average change that occurs upon altering a feature to a certain value from its mean. This is valuable because it allows us to visualise RoT explanations using the same familiar plots as SHAP explanations (e.g., the force-plots in Figure 1). This relationship also makes SHAP a natural basis for experimental comparisons with RoT.

XAI for Regulation and Auditing

Compared to other XAI methods, RoT has a range of strengths that make it an ideal tool for making existing AI systems auditable and accountable. Its robustness against adversarial attacks and fidelity compared to sensitivity-based approaches like SHAP give it a clear advantage in meeting the EU AI Act's requirements for accuracy, robustness, and adversarial testing of high-risk AI systems. Its robustness against adversarial attacks and fidelity compared to sensitivity-based approaches like SHAP give it a clear advantage in meeting the AI Act's technical requirements for robustness and resilience. This in turn, supports transparency and instructions of use requirements. RoT's computational efficiency compared to approaches requiring construction of a mimic model give it clear advantages in meeting environmental sustainability goals[8]. Most importantly, it allows auditing proprietary models, overcoming inherent transparency limitations found in many AI regulatory frameworks[9].

Enforcement of existing AI regulation often falters due to a lack of evidence, stemming from weak or missing requirements for transparency and model access for regulators, third-party auditors, and researchers[10]. Gathering sufficient evidence of potentially illegal model behaviour is highly difficult without full API access that would allow regulators to feed the model data to evaluate its responses or oversee model outputs holistically[11]. By working without model call access and requiring only observations of prior model outputs or predictions, RoT can bypass significant barriers to regulatory enforceability created by trade secrecy and confidentiality. RoT thus democratizes access to explaining and auditing AI systems. This is crucial because strong provisions enabling access or auditing by third parties (e.g., civil society organizations, vetted researchers) are uncommon in AI regulation. RoT enables participatory governance of both narrow and general-purpose AI systems, facilitating independent external testing and adversarial testing of general-purpose systems with systemic risk.

In this regard, RoT may prove particularly valuable for enforcement of the AI Act. Importantly, enforcement authorities have access to the training, validation, and testing datasets to carry out investigations into these systems. However, this is limited to dataset access, and normally does not include full model access or enable regulators to feed new data to a model to check its responses. RoT offers a clear advantage over other methods in this regard because it can compute accurate explanations using only these datasets, while others require full API access or training a mimic model.

RoT can also be a powerful tool to identify and challenge anti-competitive practices of major technology companies that are increasingly embedding AI systems across their platforms. RoT can help identify self-preferencing practices, such as search result manipulation, that may be illegal under competition laws. Establishing causality is, however, not universally required by competition law. A recent case against Google in the United States has shown that proving the mere existence of anti-competitive conditions is sufficient to show the law has been breached[12]. In this context, even if specific instances of this behaviour in a production environment cannot be shown due to a lack of access to model outputs, RoT can demonstrate that a model displays anti-competitive behaviour. Unlike measuring the sensitivity of mimic models, RoT makes no causal assumptions and thus its ability to predict behaviour of models directly makes it a stronger tool to demonstrate potentially discriminatory behaviour.

Rule-of-Thumb: Explanations Designed for Emerging XAI Applications

Explanations obtained through sensitivity-based XAI techniques often serve as an aid for users and developers in understanding and debugging model behaviour. However, they fall short in key emerging application areas: zero shot classification with LLMs, auditing black-box AI, and scientific discovery using AI.

Model Evaluation and Zero-Shot Classification with LLMs

LLMs are often used for zero-shot classification when there is no labelled dataset to train a classifier model. For each datapoint, an LLM is prompted to output a classification. Since there are no target labels to compare predictions with, typical model performance metrics such as accuracy, precision or recall cannot be readily computed. XAI offers a complementary path to performance evaluation, allowing us to inspect and verify that the "correct" features are predictive of the model's behaviour.

For example, fine-tuned language models can be used to predict the outcomes of judicial appeals from a court summary[13], or commercial LLM APIs can be used to filter resumes[14]. We consider these two applications, where a key challenge is that new predictions can be difficult to obtain for arbitrarily modified model inputs. When using commercial models, this manifests as increased costs (by default, SHAP requires 500 additional API calls to explain a single API prediction, while LIME requires 5000). Even with an open source model, this causes explanations to be prohibitively slow to compute. By contrast RoT only requires a single API call for each datapoint. To improve RoT's predictive power on text, we generate embeddings for each input token and treat these as the features, performing dropout at the token level.

From the published PredEx[13] data, we start by removing all annotations that contain hallucinations or text that we could not reliably match in the raw case text. We drop datapoints with missing case text or missing annotations, and datapoints where no text segments were found to be important or where the entire case text was found to be important. The data was annotated by law students who tried to identify text responsible for the judgement. However, the finetuned model making predictions does not always match the ground-truth predictions. Since the explanation annotations are produced from the ground-truth, but our explainers try to explain the model, there is a discrepancy. To resolve this, we drop all cases where the model predictions were incorrect, since we are interested in explaining the model but comparing our outputs with annotations which were produced independent of the model. From the remaining subset, we further drop those cases where highlighted segments were too "short" to be reliable: we enforce the condition that the minimum character length of a highlighted or non-highlighted segment in the text should be at least 75 characters. This threshold is large enough to ensure that common phrases do not get highlighted unnecessarily, and small enough to ensure we still have enough datapoints pass the filter and be included in our experiment.

This finally leaves us with a set of 502 cases, from which we compute SHAP and RoT explanations on a random 20% of cases (101 cases total). The RoT explainer we build uses the remaining 401 cases as background, but results using all 502 cases or only the 101 explanation cases as background are qualitatively similar. For the 401 case corpus, RoT is only fit on the final RoBERTa prediction per case, and not on the per-segment annotations within the case text.

We report the PR-AUC of the explanations with respect to the ground truth human annotations. Computing this metric involves comparing explanation importances (which can be negative) with human annotations (which are a binary 0 or 1). Since the annotations indicate whether text is important without direction (appeal rejection or acceptance), we post-process the feature importance by aligning them with the case prediction manually. That is, if the case appeal was rejected, we consider negative values to denote higher importance by flipping the sign of the importance for all segments, and if the case appeal was accepted, we consider the importance values as is. This way, positive values always indicate higher importance as defined by the annotators. This post-processing is not specific to RoT and is common to all explainers because it is a peculiarity arising from the PredEx data.

For RoT explanations, we use a straightforward implementation where dropout is used both on input features and on input tokens. For SHAP, we use the canonical partition explainer implementation (which defaults to 500 background samples) available for use with language models. For LIME we use the text explainer with its default bag-of-words tokenizer. By default this requires 5000 background samples, but this turns out to be prohibitively slow to compute on the entire dataset so we reduce this to 500 for PR-AUC calculations.

Auditing Proprietary Black-Box AI Systems

Explaining how a model makes predictions forms a vital component of AI auditing. Explanations reveal model behaviour and are critical for evaluating and auditing AI holistically. When explaining a proprietary AI system, model access can be restricted. With unavailable model weights and the inability to obtain model outputs for synthetically perturbed inputs, no sensitivity-based explainer can be used. One strategy is to collect observable input-output pairs from real-world model deployments, and use this dataset to build a "mimic" AI model. With unrestricted access to the mimic, predictions can be obtained on new synthetically-perturbed inputs, enabling the use of sensitivity based explainers.

In real world settings explaining mimic models instead of the original might be a simple matter of convenience[16]. Mimic models suffer from the "Rashomon effect" where they can make identical predictions to the original model, but through different internal mechanisms[17], consequently yielding different model explanations than the original[18]. RoT explanations are different, and can be computed without access to the model or the ability to obtain outputs for new inputs, using only the mimic training dataset of input-output pairs. This makes RoT valuable for enforcing regulations which do not grant third-party model or source code access, for example under the AI Act which grants regulators access only to observe model outputs on fixed input data, but not the ability to obtain new prediction on arbitrary inputs.

To demonstrate this advantage, we replicate an audit of Amazon's e-commerce recommendation system conducted by The Markup[19]. Lacking access to Amazon's recommendation system, we scrape product rankings from Amazon and use them to train a model to mimic how pairs of product are ranked relative to one another. We then explain mimic model predictions. Standard explanations reveal the most sensitive input feature is whether the product brand is Amazon ("brand is amazon"), followed by "product reviews". 📋 Methods: Amazon Recommendation Auditing

Journalists at The Markup audited Amazon's product recommendation system. Since the model used is proprietary, it cannot be queried at will, which renders all previous explainers inapplicable. To circumvent this, product recommendation data was scraped from the Amazon website, consisting of product pairs — the first and second product recommended for any particular search. A model would be built as a "proxy" to mimic Amazon product rankings, formulated as a binary classifier selecting one of the products from the scraped pair. Feature inputs to this model were also scraped, consisting of attributes like product stars (the difference in number of stars between the pair of models), and whether the picked model brand was Amazon, was sold by Amazon, shipped by Amazon, etc.

The Markup analysed this data by building a Random Forest model and then computing SHAP explanations of this model. Following this methodology, they discovered Amazon to systematically promote products from its own brand over others, as SHAP considered "brand is Amazon" to be the most important feature, and "product reviews" to be second. The model trained and explained was not arbitrary, but chosen after a typical hyperparameter search. When we replicated this audit, we found several models that were (marginally) more accurate, which are listed in Table 2.

All our models had similar accuracies and formed a Rashomon set. Their internal mechanisms were distinct, as can be verified from the global explanations. This variation is also evident from the SHAP explanations for these models, which led to different conclusions about input feature importances depending on the mimic used. All models found "brand is amazon" to be the most important input feature, but following this, subsequent features had different importances depending on the model selected.

RoT explanations, by contrast, do not require mimic models. Results obtained from RoT are therefore stronger in an auditing context, because they cannot be attributed to peculiarities in any mimic model, which can otherwise be used to absolve the original inaccessible, proprietary model.

Scientific Discovery Using XAI

Model explanations are sought not just to explain the behaviour of a model, but to also understand the underlying data it was trained on. This strategy has been advocated as a means of scientific discovery[20] in diverse fields like medicine[21], engineering[22], chemistry[23], and many more. Upon analyzing 1151 research articles at the intersection of XAI and science, we found 4.9% of them used model explanations as a means of novel scientific discovery. Of these, 70% used SHAP.

XAI use in scientific discovery suffers the same challenges as AI auditing — like mimic models, models trained to predict scientific phenomena are not guaranteed to faithfully replicate underlying causal mechanisms. Such uses are criticised because sensitivity analysis generates explanations by making predictions on synthetic, out-of-distribution datapoints, which may include physically implausible values. For these implausible, off-manifold datapoints, the behaviour of the model could be anything, and consequently the feature importances could be arbitrary[24]. By contrast, RoT importances are inspired by feature "predictiveness" rather than sensitivity, overcoming these limitations without implicitly introducing harder problems such as learning causal models or density estimation.

Identifying Uninformative Features as Unimportant

If a model shows any changes in outputs for arbitrary, out-of-distribution perturbations of an input feature, sensitivity based explainers consider that input important[24]. This definition considers a feature to be important not if it is useful to a model's predictions, but merely if it causes changes in them, even if the changes themselves are random. In this way, uninformative features can inadvertently seem important. We consider a scenario using the Pima Indians diabetes prediction dataset, transformed using FairPCA[25] to ensure that the age input feature is statistically uncorrelated with the target output — diabetes.

We consider a scenario where researchers are interested in understanding diabetes and its diagnosis. Explaining a diabetes prediction model is a common way to achieve this. On our transformed dataset, since age has been deliberately rendered uninformative, a useful XAI technique would correctly identify that age does not affect diabetes diagnoses. Identifying Important Features in the Presence of Misleading Features

We have seen that explainers can be vulnerable to out-of-distribution model behaviour. Adversarial attacks have been proposed to exploit this vulnerability[26] which modify models to explicitly use different internal mechanisms on out-of-distribution data. This effectively presents different model behaviour to SHAP or LIME than to real-world inputs. The adversarial attack masks model behaviour by hiding the actual importances of "sensitive" features and manipulating explainers into selecting misleading "foil" features as important instead.

When using XAI for scientific discovery, the inadvertent inclusion of adversarial models in the Rashomon set can cause misleading results. In black-box AI audits, this can enable "fairwashing" by allowing malicious actors to deliberately hide models with discriminatory behaviour behind benign-looking explanations. To test RoT in such a situation we construct adversarial models designed to hide the importance of an important "sensitive" feature by introducing one or more misleading "foil" features. We then generate explanations and check the relative importance of the sensitive feature compared to the foil features and other features. Across 10 experiments, for LIME or SHAP the rate of recovering the sensitive feature as most important does not exceed 5% except once, where adversarial failures (i.e., foil feature is most important) still outnumber success (i.e., sensitive feature is most important). When using XAI for scientific discovery, we want explanations not to consider uninformative input features as important. We deliberately transform the "age" feature of the "Pima Indians"[5] diabetes prediction dataset to be uncorrelated with diabetes, the target feature, and then compute explanations with various explainers to test which ones still find "age" to be important.

To make a feature statistically uncorrelated with the target, we adopt the FairPCA[25] method to transform our dataset. For our dataset with 8 input features, this transformation works by learning a low dimensional space of 7 features, such that age information is deliberately lost. By transforming our data into this space, any model trained cannot utilise age information. Finally, we learn a Logistic Regression classifier on the data, and use standard SHAP, LIME, and RoT explainers to obtain feature importances. As seen in Figure 5, we find sensitivity based explainers unable to identify the unimportance of age, but RoT does this perfectly.

📋 Methods: Adversarial Attack Resilience

We consider a scenario where an adversary tries to mislead explainers into selecting spurious "foil" features as important, instead of the "sensitive" features the model actually uses to make decisions.

We use the same datasets as those used in the paper proposing the adversarial attack[26], and follow its setup exactly: for the COMPAS[27] and Communities & Crime[28] datasets, the "sensitive" feature is "race" whereas for the German Credit[29] dataset it is "gender". All models are binary classifiers formulated as simple if statements depending on the sensitive feature, predicting recidivism risk for the former two datasets, and loan repayment probabilities for the latter.

The "foil" attributes used are synthetically added features for COMPAS and Communities and Crime, whereas for the German Credit dataset, the foil used is not synthetic but a new feature that is a function of other input features. Further, instead of 3 experiments (one for each dataset), for COMPAS and Communities and Crime we conduct experiments twice — once with a single synthetic foil, and once with 2 synthetic foils. The adversary modifies models to mislead explainers. These modifications work can be tailored to the particular perturbations used by a sensitivity based explainer, and we consider models designed to mislead both SHAP and LIME, comparing both with RoT.

Like in the original paper, this setup leads to 5 experiments with each explainer: 1 German Credit, 2 COMPAS, and 2 Communities and Crime. For each datapoint in each experiment, we consider the absolute importance of the sensitive feature, average absolute importance of the foil features, and average absolute importance of all other features, forming a sample from a ternary distribution. Benchmark XAI Evaluations and Computational Efficiency

As demonstrated, RoT has clear benefits in emerging XAI applications of scientific discovery, auditing, and LLM explanation. We now analyse RoT in traditional tabular modalities using existing XAI benchmarks, where it is a drop-in replacement for other explainers. We observe RoT produces similar explanations as SHAP but is more computationally efficient.

Benchmark Evaluations of RoT Explanations

Sensitivity analysis underlies XAI evaluation benchmarks the same way it underlies explainers themselves. The OpenXAI benchmark[30] is a popular benchmark, but unfortunately suffers errors that systematically promote gradient based explainers. OpenXAI evaluates explanations using either "perturbation" based metrics, which are explicit variants of sensitivity analysis, or "ground-truth" comparison based metrics. These function by training Logistic Regression models and comparing local explanations for any input datapoint with global model coefficients. This formulation sets the "ground-truth" explanation to be identical for every datapoint, promoting a single explanation as correct for all datapoints, regardless of the specific input feature values. This promotes LIME over other sensitivity explainers due to its sampling kernel, and also guarantees that gradient-based explainers would recover these "ideal" explanations[31] exactly.

OpenXAI considers Logistic Regression coefficients as the "ground-truth" explanation for all datapoints. Regardless of the specific feature values for a given datapoint, such ground-truth comparison metrics consider a single explanation as ideal across all input datapoints, promoting a single unchanging explanation. Using Logistic Regression coefficients OpenXAI deliberately promotes gradient methods or LIME, which are Taylor-series like approximations of model behaviour and can recover the Logistic Regression coefficients exactly for any input datapoint. While these explainers score better than SHAP in the published OpenXAI benchmark scores, they are undesirable in practice because they cannot explain individual predictions and always produce identical feature importance outputs. Due to these aforementioned issues, instead of reporting the official metrics from OpenXAI, we adopt the benchmark to verify that RoT behaviour mirrors SHAP, and every input datapoint does not yield the same explanation output.

Only the SHAP and RoT explainers show desirable behaviour, where the local explanation is truly a function of the datapoint being explained. LIME and gradients show the same feature importance regardless of the feature values, undermining the usefulness of OpenXAI metrics which consider these explanations to be the best. Runtimes and Computational Efficiency

Many local explainers function by collecting data about model behaviour and then fitting an interpretable model. Sensitivity based explainers like SHAP and LIME collect data by perturbing inputs and fitting a new interpretable model for each explanation. This requires data collection by making arbitrarily time-consuming calls to the model for each additional explanation. By contrast, RoT fits a single interpretable model on the entire unperturbed dataset, and each explanation is generated using per-feature outputs from this model. Since model inference is quicker than training, this makes computing explanations extremely fast once RoT is fit. It also reduces the environmental footprint of computing explanations by eliminating the need to train new interpretable models or generate extra predictions on perturbed inputs. This latter component can be very computationally expensive in modern AI applications, as we noted in our judicial case prediction experiment, where SHAP required significant resources and LIME was rendered completely unviable at scale.

In practice it is impractical to compute SHAP or LIME explanations for LLM predictions, except in rare cases where only a handful of datapoints need explaining. Gradient methods are quicker, but require model access which is also unavailable in practice over commercial APIs. RoT is the first explainer that can actually be deployed in practice, bringing feature importance XAI to LLMs. For judicial case outcome prediction, the first RoT explanation took 1160 seconds, and each additional explanation took less than 0.1 milliseconds. By contrast, the average time taken for each SHAP explanation was 1320 seconds. On tabular data we find similar behaviour, where RoT is orders of magnitude faster than SHAP and LIME, despite including explainer initialisation times.

📋 Methods: Runtimes and Computational Efficiency

All runtime measurements were conducted on standard hardware, comparing the wall-clock time required to compute explanations across all experiments discussed in this paper. For judicial case outcome prediction with LLMs, we measured the time to fit the RoT model and compute explanations for 101 cases, compared with SHAP explanations computed over the same 101 cases. For tabular data experiments, we computed explanations across all test datapoints from the auditing, fair PCA, and adversarial attack experiments, as well as using the OpenXAI pretrained models and provided datasets. Wall-clock times include all preprocessing, model fitting (where applicable), and explanation generation, but exclude data loading and input feature computation.

Conclusion

This paper presents a new approach to explainable AI based on the predictiveness of feature values, rather than their sensitivity to alteration. This rule of thumb approach allows us to approximate any decision making process by summing the importance response over any subset of features values. The most useful feature values for a prediction are naturally those with largest importance, and their predictive power overrides the contribution of others. In this way, RoT is a post-hoc local explanation method inspired by ablation studies, rather than sensitivity analysis.

This approach addresses several long-standing concerns in the community about the validity and practical utility of XAI, and importantly does so without making additional assumptions. It is flexible and useful in a range of emerging XAI applications areas where other forms of XAI simply cannot be used — evaluating LLMs and explaining their behaviour in zero-shot classification, auditing proprietary AI systems where we can only observe their predictions and not alter input features, and using XAI to understand real-world phenomena and propose novel scientific hypotheses. As a local, post-hoc explanation method, RoT can be used as a drop in replacement for other explainers in existing XAI codebases, and visualised the same way, providing an exceedingly fast and environmentally friendly method of explaining AI model behaviour.

Appendix A: Motivation and Related Work

Explainability in Machine Learning, Feature Attribution Methods, and SHAP

Machine learning models range from inherently interpretable (e.g., decision stumps, linear regressions, rule-sets, or single nearest neighbour classifiers) to uninterpretable black boxes (e.g., random forest ensembles, deep neural networks, or Markov random fields). In order to explain black-box models, methods have been developed to produce post-hoc model explanations (e.g., saliency maps, counterfactual explanations, anchors, prototypes, etc.). These can be either global, explaining model behaviour in general (e.g., PDPs, Functional Decomposition, Mechanistic Interpretability, etc.), or local, explaining individual predictions made by a model (e.g., ICE, LIME, anchors, counterfactuals). Some model explanation methods are specific to certain kinds of models (e.g., TCAV, Saliency Maps, gini-importance), whereas others are considered to be model agnostic (counterfactual explanations, LIME, anchors, etc.). SHAP is a widely used model-agnostic, post-hoc, local explanation method that produces scores indicating the relative importance of various input features that led to a model prediction [1]. SHAP is often the first technique used by practitioners interested in explaining the behaviour of black box models.

Explainability in Experimentation and Production

One use of explainability in machine learning is to continuously explain the predictions being made by artificial intelligence systems that have been deployed in the real world. This can help debug errors [2], comply with regulations, and engender trust [3]. Often, explanations are used to gauge if protected attributes are significantly impacting model outputs and bring transparency to otherwise opaque decision making processes [4]. When models are being deployed in real world settings and affecting large numbers of users, it can be important to monitor their behaviour and have explainability in production, which requires explanations to be computed in a scalable manner.

A different use of explainability is in the lab, where researchers may want to understand model behaviour in order to study underlying phenomena. When using explainability during model development or exploratory data analysis, explanations can be used to understand the data generating process itself. Using explainability techniques such as SHAP has been proposed as a means of scientific discovery [5][6][7][8][9]. This strategy has been employed in diverse fields such as policy-making [10], physics [11], engineering [12][13], epidemiology [14][15], chemistry [16][17], healthcare [18], ecology [19], and geology [20]. In these fields, model explanations are used to derive insights about underlying natural phenomena using a machine learning model, rather than explain the behaviour of a model used in decision making. This can be termed explainability in experimentation, and requires explanations to be robust and consistent.

These two use cases for model explanations are different, and present themselves with different desiderata and technical challenges. Rule of Thumb provides a scalable method that is important in production settings, as well as a robust method that does not suffer from causal vulnerabilities or the Rashomon effect important in experimentation settings.

Implicit Assumptions about Causality

Machine learning classification is concerned with learning the conditional probability of obtaining a response $y$ from a given set of inputs $x$. Borrowing from Judea Pearl's causal hierarchy [21], this involves "level 1" reasoning—the ability to observe associations. There is broad consensus today that machine learning alone is unable to produce systems with higher "level 2" or "level 3" reasoning abilities involving the ability to answer "interventional" and "counterfactual" questions, respectively [21].

The AI explainability literature has been surprisingly forgiving of this deficit typical in all modern machine learning systems. Sensitivity-based model explanation methods like SHAP implicitly assume that models produce predictions using level 3 reasoning. If a model only possesses "level 1" observational reasoning, but an explanation method probes it with inputs that do not exist in naturally observed training data, then model predictions in these regions cannot be considered indicative of model behaviours.

SHAP's reliance on perturbing model inputs causes explanations to be overly sensitive to out-of-distribution model behaviour, which can be arbitrary [22]. The solutions proposed to this problem, such as manifold-SHAP [23] or causal SHAP [24], necessarily involve solving harder problems of density estimation [25] or causal modelling [21], as opposed to learning a simpler classifier decision boundary. Adversarial attacks have been proposed to exploit this vulnerability, and it has been shown that explanations can be manipulated this way, leading to fair-washing [26].

While these two approaches are theoretically possible, the associated problems often make them impossible to implement in practical scenarios. These problems are especially pronounced for uses of model explainability in experimentation, where many models are built and explained iteratively, and the focus is more on the explanations themselves than on deploying the model to real-world production settings. In such scenarios, requiring the user to first build a causal model or estimate the entire density of the data is impractical.

By contrast, Rule of Thumb makes no causal assumptions about the model and does not need to solve the "harder" problems of density estimation either. Rule of Thumb generates explanations entirely through "level 1" observation.

Ablation Studies and Sensitivity Analysis

Feature importances can be motivated in at least two distinct ways, involving the effect of:

  1. Removing or ablating input features on model outputs to determine feature importances through their predictiveness (ablation studies); or
  2. Perturbing input features and measuring the corresponding perturbations on model outputs to determine feature importances through their impact on the model output (sensitivity analysis).

Both these notions have been used widely. Examples of sensitivity analysis include applications in chemistry [27][28], geology [29][30], and engineering [31]. Ablation studies have roots in medicine and are widely used in machine learning [32] today, and sometimes in other fields like physics [33][34] and biology [35][36].

Problems with Model Explanations in Practice

Returning to examples of trying to debug large language model behaviour by explaining their classification outputs and of trying to monitor large-scale proprietary e-commerce recommendation systems, we can illustrate the common practical problems when explaining machine learning predictions.

When trying to explain the behaviour of an LLM, it is not possible to arbitrarily modify the input features to the model. For an explanation method like SHAP, it then becomes unclear how to perturb the input features. Additionally, explanations can only be used to ascribe importances to input features, and nuanced analyses studying the relationship between the output and external concepts or latent features is difficult. Rule of Thumb is useful because not only does it not rely on input perturbations, but also because it allows the inclusion of external concepts when generating model explanations. TCAV is a global explanation method that explicitly uses latent concepts to provide model explanations [37], but Rule of Thumb is able to do this on a local, per-prediction level.

When trying to audit the behaviour of proprietary systems, often model artifacts cannot be accessed to obtain output predictions for new input points. This makes explanation methods like SHAP impossible to use without first creating a model to mimic the original. In real world settings, it is often easier to explain such a mimic model, rather than explaining the actual model [38][39], and it is hard to assert that the mimic explanations generated also apply to the original model due the predictive multiplicity of classifiers [40]. This "Rashomon effect", where two models have similar predictions but different internal mechanisms [41], makes model explanations obtained using a mimic model inherently untrustworthy when explaining the original model behaviour [42]. Rule of Thumb sidesteps this issue entirely and does not need access to a model at all; it generates model explanations instead by looking at its predictions.

Appendix B: Mathematical Derivation and Formulation

We wish to explain the behavior of a model $C(\cdot)$, over an empiric data distribution $X$. Given a data-point, $x \in X$, we use $x_j$ to refer to the $j^{\text{th}}$ component of the feature vector of $x$. We will define our explanations as a set of functions, similarly indexed by $j$, and refer to $f_j(x_j)$ as the importance of $x_j$. Given an arbitrary subset of features $J \subseteq \mathbb{J}$ over a data-point $x$, we wish to be able to make predictions about the model response $C(x)$ using only the sum of importance weights $\sum_{j \in J} f_j (x_j)$.

In this way, we wish to be able to make a prediction about the model response $C(x)$ using incomplete information about the feature vector of $x$, where only $j \in J$ of the feature values are known. The $f_j(x_j)$ individually serve as feature importances, and when summed are used to predict the model output.

Formulating Explanations from Incomplete Information

We give a general formulation suitable both for modelling discrete decisions using a logistic regression approximation, and for modelling continuous regression tasks using a linear regression approximation. In practice, these can be replaced with any additive model.

The functions $f_j$ are parameterized by weights $\theta_j$ and the model is approximated by a function $F$ of their sum and a global bias term $G$. Recall that we want to find the optimal set of additive functions $f$ such that for any data point $x \in X$ and arbitrary subset of features $J$ we can approximate $C(x)$.

$$C(x) \approx F \left( \sum_{j \in J} f_{\theta_{j}}(x_j) + G \right) \;\; \forall J \in \mathcal{P}(\mathbb{J})$$

As mentioned above, we use the linear and logistic approximations of $C(\cdot)$, in which $f_{\theta_j}(x_j) = a_jx_j+b_j$. In the case of linear regression, $F$ is the identity function, whereas for logistic regression, $F$ is the logistic function $\sigma$.

For regression models, this yields:

$$C(x) \approx \sum_{j \in J} \left( a_jx_j+b_j \right) + G \;\; \forall J \in \mathcal{P}(\mathbb{J})$$

and for classification this yields:

$$C(x) \approx \sigma \left( \sum_{j \in J} \left( a_jx_j+b_j \right) + G \right) \; \; \forall J \in \mathcal{P}(\mathbb{J})$$

For regression models, we minimise the mean squared error, further simplifying the regression equation above. The per-feature bias term $b_j$ can be disregarded if the mean of every feature $j$ is $0$, and the global bias term becomes equal to the mean model response $\overline{C}(x)$.

For classification models, we maximize the likelihood by marginalising over a distribution of randomly sampled features. We seek the values of $\theta_j$ that minimize the expected loss $\mathbb{L} [\cdot,\cdot]$ (typically cross-entropy error) over all subsets of features $J \subseteq \mathbb{J}$ and data-points $x \in X$:

$$\min \; \; \sum_{ J \subseteq \mathbb{J}} \left( p^{ |J| } \; (1-p)^{(|\mathbb{J}|-|J|)} \; \cdot \; \sum_{x \in X} \mathbb{L} \left[ C(x), \;\; \sigma \left( \sum_{j\in J}f_{\theta_{j}}(x_j) + G \right) \right] \right)$$

Like the formulation of SHAP, this objective is exponentially large with respect to the feature space. However, a key difference that allows us to solve it effectively is that the number of function calls to $C$ is equal to the number of data points $|X|$, and is completely independent of the feature space $J$. By commuting, this is equivalent to:

$$\min \; \; \sum_{x \in X} \sum_{ J \subseteq \mathbb{J}} \left( p^{ |J| } \; (1-p)^{(|\mathbb{J}|-|J|)} \; \cdot \; \mathbb{L} \left[ C(x), \;\; \sigma \left( \sum_{j \in J}f_{\theta_{j}}(x_j) + G \right) \right] \; \right)$$

Upon careful inspection, this is equivalent to performing dropout with probability $p$ [43] on the initial approximation model $\sigma \left( \sum_{j \in J}f_{\theta_{j}}(x_j) + G \right)$. This allows us to directly find the weights $\theta_j$ (recall we defined $f_{\theta_j} = a_jx_j + b_j$) and $G$ using stochastic optimization by treating this as a regression problem regulated by dropout. Implementation of the method is straightforward, with the only subtlety being that the weights and biases should be zero-initialized to avoid problems with vanishing gradients in the logistic regression loss.

Uniqueness and Stability

Each component of the objective defined above is convex. As such, if for every estimated variable there exists a strictly convex component containing that variable, the problem as a whole is strictly convex. Therefore, the overall objective has a unique minimum provided the individual functions $f_{\theta_j}(\cdot)$ are well-posed and strictly convex with each function having a single minimum associated with it.

From Approximation Model Weights to Interpretable Feature Attributions

The optimization procedure returns a set of functions $f_{\theta_{j}}$ that then need to be applied to each feature. The response $f_{\theta_{j}}(x_{j})$ can be directly interpreted as a signed measure of the importance of feature $j$ on data-point $x$. For logistic regression, the sum $\sum_{j \in J}f_{\theta_{j}}(x_{j})$ can be directly interpreted as probability in logit space of the classifier response $C(x)$; while for linear regression, the same sum is an estimate of the model prediction $C(x)$.
